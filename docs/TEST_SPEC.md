# テスト仕様・完了条件

以下は実装後の受入れ項目。機能追加時に自動テストと実機確認の双方で該当項目を確認する。Phase 0のSDK型検査と標準IME実測の状況は[アーキテクチャ](ARCHITECTURE.md)を参照。

## 1. 入力と状態遷移

- ローマ字入力が意図したひらがなになる（促音、拗音、長音、撥音、未完了のローマ字列を含む）。
- 日本語モードで全角、英字モードで半角となる。モード切替が確定したキー表どおり。
- 変換操作まで候補が表示されない。ライブ変換・予測変換・サジェストがない。
- 変換要求後の候補表示、確定・取消が確定キー表どおりに動く。確定済み文字の再変換は採用された場合に確認する。
- Space、Return、Escape、矢印等を、入力中/変換中/空状態ごとに確認する。
- 句読点の入力が自動変換・確定を起こさない。日本語モードの `,` は「、」、`.` は「。」。
- `Ctrl+K` が読みをカタカナにし、未確定状態を保ち、Enterで確定できる。
- 文節単位・文章全体の変換、文節移動・伸縮を確認する。

## 2. 候補と順位

- 一覧全ページ、単文節・全体変換、番号選択や直接確定に絵文字が出ない。同じ文字にテキスト表示と絵文字表示がある場合や、数字が絵文字判定に巻き込まれない場合も確認する。
- 読みから英単語・英字表記へ変換されない。英字モードでの直接入力は可能。
- 入力中に変換候補・予測候補が出ない（UI自動検査と実機確認）。
- 学習データがなく、同じエンジン・辞書・設定で同じ入力の候補順が再現される。
- ユーザー辞書の一致語が最上位。複数語の競合・同音異義・同順位の扱いを確認する。
- カタカナ対漢字の一般順位は確定したポリシーに照らしてテストする。ポリシー確定までは期待値を固定しない。

## 3. 辞書

- 単語の登録、編集、削除、再起動後の永続化。
- Apple標準IMEが実際に書き出した架空語のplistで、正常インポートと対応するデータ型を確認する。重複、未知フィールド、不正行、空ファイル、候補除外と衝突する語、途中失敗時に既存データが保たれることを確認する。
- インポートした語が候補に現れ、最上位規則に従う。
- インポート元データがネットワークに送られず、ログにも出ない。

## 4. オフライン・プライバシー

- ネットワークを切断して起動、入力、変換、辞書、設定を利用できる。
- アプリの通信を監視し、入力/変換時およびアイドル時に外向き通信が発生しない。
- ログ、設定、クラッシュ情報に入力全文や不要な個人情報が含まれない。
- 同梱辞書/モデルが完全にローカルで使用できる。

## 5. UI・互換性

- macOSライト/ダークモードで候補パネルと設定画面を確認する。
- キーボード操作、読み上げ/アクセシビリティ、候補ウィンドウの画面端・複数画面配置を確認する。
- 主要な編集アプリ、ブラウザ、ターミナル、IDEで入力、候補、確定、取消、カーソル移動を確認する。
- IME切替、アプリ切替、スリープ復帰、フルスクリーン、リモート/セキュア入力場面の挙動と制限を確認する。
- Apple Siliconの最小対応バージョンと対応対象の各OS世代でインストール、更新、アンインストールを確認する。配布物を用いた検証では全実行コードがarm64で、オンラインとオフラインのGatekeeper導入経路を確認する。

## 6. OSS準備

- 配布対象となる全コード、依存、辞書、モデル、画像、フォントの取得元・バージョン・ライセンスを一覧化。
- ライセンス条件、NOTICE、ソース提供義務、再配布条件に不明点が残らない。
- クリーンな環境で文書どおりビルドできる。対象OS、署名・公証、既知制限を明記する。

## 7. 完了判定

必須要件に対する未解決失敗がなく、実機テスト結果と既知制限が記録され、利用者が変換順位と操作性を評価できる状態であること。変換精度は機械的なテストだけで合格とせず、利用者の確認を含める。

## Phase 1の実機確認

開発用アプリを入力ソースに追加し、横書きのTextEditで入力メニューから日本語を選ぶ。

1. ローマ字が下線付きのひらがなになる。続けて数字とコンマ・ピリオドを押すと全角数字と「、」「。」が同じ未確定範囲に追加される。
2. Ctrl+Kでカタカナの下線が残り、Returnで確定する。新しい入力はひらがなで始まる。
3. 未確定の状態でSpaceを押すと未確定のまま維持される。Escapeで取り消したあと、Spaceで全角空白が入る。
4. 入力メニューから英字へ切り替えると英字・数字・空白が半角で入力される。Ctrl+Shift+JとCtrl+Shift+;による切替も確認する。
5. ブラウザの入力欄でも未確定表示、Return、Escapeを確認する。

ローマ字変換と状態遷移の自動テストは `swift test --arch arm64` で実行する。

## Mozc付き開発版の統合テスト

READMEの手順で開発用バンドルをビルドし、環境変数 OMIYAIME_TEST_BUNDLE にバンドルのパスを指定して SwiftPM テストを実行する。候補のない入力中は変換器を呼び出さず、明示変換で実辞書を使い、同一条件での再現と文節伸縮を確認する。

実機では上記に加え、候補表示までのSpace、左右と上下、Shift+左右、Return、Escape、アプリ切替を確認する。設定画面では単語の追加・変更・削除、再起動後の保存、plistのインポート前確認、ライト／ダークの表示を確認する。
