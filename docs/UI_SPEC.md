# UI仕様

## 方針

Mac標準IMEの候補ウィンドウを好む利用者のため、macOSに自然になじむ、情報量を絞ったUIを目指す。候補UIは変換要求後にだけ表示する。未変換中の候補・予測・サジェスト・絵文字・英訳を表示しない。

## 候補ウィンドウ

### 確定事項

- 候補操作と表示タイミングはMac標準IMEの操作性を目標とする。
- 候補には日本語変換結果を表示し、絵文字および英単語変換候補を含めない。
- 入力中、変換を要求する前の候補表示は行わない。
- 視覚装飾は必要最小限。

### 検証・設計項目

- 候補パネルの位置、寸法、候補数、ページ送り、選択強調、文節表示は標準IMEを実測して定める。
- アプリごとの入力コンテキスト、画面端、複数ディスプレイ、フルスクリーン、アクセシビリティを検証する。
- 候補ウィンドウの実装手段は公開APIの範囲で技術検証し、公開の `IMKCandidates` を第一候補とし、選択と確定を区別できるか、候補操作時も入力先にフォーカスが残るか、VoiceOverで操作できるかを先に確認する。必要に応じてAppKitの候補パネルを比較する。
- 2026-11-27: `IMKCandidates` の選択強調が、上下キー・Spaceで選んだ候補と一致しない現象を実機で確認した（macOS 26.5.2）。このため、入力先のフォーカスを奪わない独自のAppKitパネル（`CandidateWindow`）に切り替えた。1ページ9件、番号付き、角丸12pt・文字17pt（2026-11-27 利用者の好みで調整）、選択行を強調し、候補間に薄い区切り線を入れ、番号は控えめな色にする。次のページがあるときだけ右下に小さな下向き矢印を表示する（件数表示は利用者の希望で廃止）。クリックでその候補に確定する。VoiceOver対応は未検証。
- 数字付き候補ラベル等の具体的表示は、標準IME確認後に決定する。候補パネル自体の選択・ページ操作と、ホスト側テキストの確定を区別して確認する。

## 設定画面

- macOS標準の設定画面に近い見た目と操作感にする。
- ライトモード、ダークモードに対応する。
- 初期設定項目はモード・入力動作、辞書の管理とインポート、キー割当（確定した場合）の範囲に抑える。
- 学習機能の切替項目は、学習機能自体を将来実装する段階で追加する。初期版に機能や有効化UIを作らない。
- 変換に関係ないアカウント、同期、ネットワーク、広告等の画面を設けない。
- 設定UI技術は未選定。macOS標準UIとの一貫性、アクセシビリティ、保守性を検証する。

## 品質要件

- macOSのシステム外観に追従し、文字コントラストと選択状態を確保する。
- キーボード操作だけで設定と候補操作を完結できる。
- 候補表示・設定UIから入力内容が外部へ送られない。

## 入力メニューのアイコン
