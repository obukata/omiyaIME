## 目的

ゲームとしての目的やクリア条件はない。仕事でもプライベートでも、たくさんキーを打つと、柴犬のおみや君をかわいがる時間が増える。それを楽しみにしてもらうための機能。（2026-11-27 利用者回答）

## 守ること（既存の要件からの制約）

- 数えるのは、キーを打った**回数だけ**。どのキーを打ったか、何を入力したかは記録しない。ログ、テレメトリ、クラッシュ報告にも入れない（AGENTS.md）。
- ネットワーク通信をしない。データはこのMacの中だけに保存する。
- 入力のじゃまをしない。文字入力中のアプリからフォーカスを奪わない。
- 設定でOFFにできる（ROADMAP「将来バックログ」での前提）。

## 技術的な前提（確認が必要なもの）

- IMEがキーを受け取れるのは、おみやIME（ひらがな・英字）が選ばれているときだけ。ほかの入力ソースを選んでいる間のキーは数えられない。
- パスワード欄など「セキュア入力」の間は、macOSがIMEにキーを渡さない。そのため数えない（実機で要確認）。
- ペットの窓は、IMEの中から出す、フォーカスを奪わない窓にする案がある。候補ウィンドウと同じ方式。別アプリにするかは未検討。

## 試作（2026-11-27）

IMEに組み込む前に、見た目を確かめるための試作。IMEを入れ直さずに動かせる。

- `Sources/OmiyaWalk/`：表示部品（`WalkView`、`WalkPanel`）と仮素材。あとでIMEから使う
- `Sources/OmiyaWalkPreview/`：試作を画面に出すだけの小さなアプリ
  - 起動：`swift run omiya-walk-preview`。右クリックの「終了」で閉じる

- フォーカスを奪わない窓（`nonactivatingPanel`）。円の外の透明な部分は、クリックが下の窓に届く

仮素材の作り方（素材の差し替えまでの暫定）：

- 柴犬：歩く絵は、白い背景を周りから塗りつぶすようにして透過にした。動作の絵はもともと透過だった
- 座り・眠り（2026-11-27 追加の下書き）：もともと透過。立ち姿の背の高さで縮小し、鼻先の位置を歩く絵にそろえた。`sit_4` だけは顔の向きが違うので、`sit_3` と絵が一番重なる位置に合わせた（右に7.5pt）。鼻息の線にも「zz」と同じ白いふちを付けた
- 各コマは、立ち姿の背の高さが同じになるように縮小した
- 240×160pxのキャンバスに入れ、足元の線と、番号の位置を中心としてそろえた。2倍解像度で使う
- 背景：元の画像をそのまま使う

## 宝物と穴掘り（2026-11-27 実装）

- 抽選（`DigRule`）：掘るたびに、50%で何かが出る。出たときのめずらしさは、ふつう85%、ちょっとめずらしい13%、激レア2%。同じめずらしさの中では、どれも同じ確率。数字は仮で、あとで調整できる
- 同じ宝物を何度も見つけてよい。一覧では2回目から「×2」のように回数を出す
- 抽選と記録はIMEが行う（歩数を保存するときに、1kmの区切りを越えたかを見る）。表示側が動いていなくても、見つけた宝物は記録される
- 記録は `walk.json` の `found`（宝物ごとの回数）、`digCount`（掘った回数）、`lastFind`（最後に見つけたもの）。打ったキーや内容は入れない
- アニメーション：掘るコマ（`dig_0`〜`dig_7`）を2回くり返して2秒、顔を上げるコマ（`sniff_0`〜`sniff_5`）で1秒。何か出たときは、その宝物の絵と名前を、おみや君の上に3秒出す（白いふち付き、少し上下に揺れる）。掘っている間、街は止まる
- 「拾う（アイテムあり）」のコマは、くわえている物が木の枝の絵なので、今は使っていない
- 表示側が動いていない間に掘った分のアニメーションは出さない。次に表示側が新しい掘りに気づいたときに、最新の1回分だけを見せる
- 試作アプリの右クリックと歯車のメニューに「（試作用）いま掘る」を付けた。1kmを待たずに掘れる。見つけた宝物は本当に記録される。正式版では外す
- この仕組みを入れる前に歩いた分（3km分）は、さかのぼって掘らない

## 音（2026-11-28 実装）

- 掘る音（`dig.wav`）：土をひっかくような短い音。掘るコマの1コマおき（毎秒4回）に鳴らす
- 宝物が出たときの音（`find.wav`）：ピロリン、と上がっていく短いファミコン風の音。宝物の絵が出た瞬間に1回鳴らす。何も出なかったときは鳴らさない
- どちらも、既存の素材を使わず、`Scripts/make-walk-sounds.py` で波形を計算して作った仮の音。著作権の問題はない。正式な素材に差し替えるときは、その素材のライセンスを確認する
- 音のアイコン（スピーカーの絵）は宝箱と歯車の間（右から28.5度）。押すたびにオン・オフが切り替わる。オフのときは、スピーカーに×を付けた絵になる。マウスを乗せると今の状態が出る
- 最初はオン。設定は試作アプリの設定（`UserDefaults` の `omiyaWalk.soundOn`）に覚える。表示をIMEに入れる場合は、置き場所を見直す
- 音量は、Macの音量に対して60%

## 距離の記録（2026-11-27 実装）

- IME（`InputController.handle`）が、キー押下のたびに歩数を1つ増やす。記録するのは歩数だけで、どのキーか、何を入力したかは記録しない。
- 歩数は `~/Library/Application Support/omiyaIME/walk.json` に `{"steps": 歩数}` として保存する。キーのたびに書かず、最大2秒ごとと、IMEの入力が終わるとき（`deactivateServer`）にまとめて書く。
- 表示側は、このファイルを約1秒ごとに確認して距離を更新する。
- 計算と保存は `Sources/OmiyaWalkCore/`（`WalkProgress`、`WalkProgressFile`、`WalkStepCounter`）。テストは `Tests/OmiyaWalkTests/`。
- IMEが数えるのは、おみやIMEが選ばれている間だけ（「技術的な前提」を参照）。この数え方は、ブランチの版のIMEを入れたときから有効になる。
