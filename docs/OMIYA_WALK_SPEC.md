# おみや君のお散歩（ゲーミフィケーション）仕様

状態：**仮の仕様（検討中）**。ブランチ `feature/omiya-walk`。ここに書いたことだけを実装する。「未決」の項目は、利用者の回答を得るまで実装しない。

## 目的

ゲームとしての目的やクリア条件はない。仕事でもプライベートでも、たくさんキーを打つと、柴犬のおみや君をかわいがる時間が増える。それを楽しみにしてもらうための機能。（2026-11-27 利用者回答）

## 決まったこと（2026-11-27 利用者回答）

| ID | 内容 |
|---|---|
| W-01 | キーを打った回数に応じて、お散歩ポイント（お金の扱いになる可能性もある）が貯まる。 |
| W-02 | ポイントを使って、おみや君の服、ハーネス、便利アイテムを買える。 |

| W-04 | コレクションのアイテムは、ゲームを有利にしない。集めるだけのもの。例：お気に入りの骨、桜の木の枝、アヒルのおもちゃ、野球ボール。 |

| W-08 | 背景は、街の画像（2枚目の下書き）を使う。 |

## 守ること（既存の要件からの制約）

- 数えるのは、キーを打った**回数だけ**。どのキーを打ったか、何を入力したかは記録しない。ログ、テレメトリ、クラッシュ報告にも入れない（AGENTS.md）。
- ネットワーク通信をしない。データはこのMacの中だけに保存する。
- 入力のじゃまをしない。文字入力中のアプリからフォーカスを奪わない。
- 設定でOFFにできる（ROADMAP「将来バックログ」での前提）。

## 技術的な前提（確認が必要なもの）

- IMEがキーを受け取れるのは、おみやIME（ひらがな・英字）が選ばれているときだけ。ほかの入力ソースを選んでいる間のキーは数えられない。
- パスワード欄など「セキュア入力」の間は、macOSがIMEにキーを渡さない。そのため数えない（実機で要確認）。
- ペットの窓は、IMEの中から出す、フォーカスを奪わない窓にする案がある。候補ウィンドウと同じ方式。別アプリにするかは未検討。

## 素材（2026-11-27 時点の下書き）

利用者がChatGPTで作ったドット絵の下書き。まだリポジトリには入れていない。

- 柴犬の動き
  - 歩く：4コマ
  - 地面を掘る：8コマ、くり返し
  - 拾う（何もなし）：6コマ
  - 拾う（アイテムあり）：6コマ。例として木の枝をくわえる
- 背景：朝の街並み。カフェ、自動販売機、ベンチ、バス停、自転車などがある

実装に使う前に必要なこと：

- 1コマずつ、背景を透明にした画像にする。下書きには、文字、番号、市松模様の背景が入っている。
- 全コマを同じ大きさの画像にし、同じドットの細かさ（グリッド）にそろえる。
- 背景を横にスクロールさせる場合は、左端と右端がつながる絵にする。
- 使ったAIツールと利用規約を、ARCHITECTURE.md のライセンス表に記録する。生成物の扱いを確認する。

## 試作（2026-11-27）

IMEに組み込む前に、見た目を確かめるための試作。IMEを入れ直さずに動かせる。

- `Sources/OmiyaWalk/`：表示部品（`WalkView`、`WalkPanel`）と仮素材。あとでIMEから使う
- `Sources/OmiyaWalkPreview/`：試作を画面に出すだけの小さなアプリ
  - 起動：`swift run omiya-walk-preview`。右クリックの「終了」で閉じる
  - `--snapshot 出力.png [秒]` を付けると、画面に出さずに1枚の画像を書き出して終わる
- フォーカスを奪わない窓（`nonactivatingPanel`）。円の外の透明な部分は、クリックが下の窓に届く

仮素材の作り方（素材の差し替えまでの暫定）：

- 柴犬：歩く絵は、白い背景を周りから塗りつぶすようにして透過にした。動作の絵はもともと透過だった
- 各コマは、立ち姿の背の高さが同じになるように縮小した
- 240×160pxのキャンバスに入れ、足元の線と、番号の位置を中心としてそろえた。2倍解像度で使う
- 背景：元の画像をそのまま使う
