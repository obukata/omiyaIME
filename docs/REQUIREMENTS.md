# 要件定義

## 1. 目的

Mac標準IMEの変換体験と自然なmacOS UIを好む利用者向けに、余計な候補や先回り動作を避け、意図したときだけ日本語変換するIMEを作る。特に絵文字候補が出ることを最も避けたい。英語は英字モードで入力し、読みから英単語へ変換する機能は求めない。

## 2. 確定要件

| ID | 要件 |
|---|---|
| R-01 | macOS専用。対象CPUはApple Siliconのみ。最小対応の目標はmacOS 26.0。対応表明には26.0の実機検証を要する。 |
| R-02 | 完全オフラインで動作し、入力・変換のためのネットワーク通信を一切行わない。 |
| R-03 | 日本語の入力方式はローマ字入力のみ。 |
| R-04 | 日本語入力モードでは全角、英字入力モードでは半角で入力する。 |
| R-05 | 入力モード切替と変換・候補操作はMac標準IMEに準拠した操作性を目指す。細部は検証課題。 |
| R-06 | ひらがな、漢字、文節変換を提供し、文節単位と文章全体の変換の双方を使える。 |
| R-07 | 変換前のライブ変換、予測変換、入力中の候補・サジェスト表示を行わない。変換を明示的に要求した後に候補を表示する。 |
| R-08 | 絵文字を変換候補に含めない。候補順位を下げるだけでなく、候補集合から除外する。 |
| R-09 | 読みから英単語・英語表記を候補化しない。英単語は英字入力モードで入力する。 |
| R-10 | `Ctrl+K` で読みをカタカナにする。変換後は未確定のまま維持し、Enterで確定できる。通常の変換順位でカタカナをどう扱うかは未決。 |
| R-11 | 句読点キーで変換・確定を自動実行しない。日本語モードでは「、」「。」を入力する。 |
| R-12 | ユーザー辞書の登録・編集・削除を行える。辞書登録語は変換候補で必ず最上位にする。 |
| R-13 | Mac標準IMEのユーザー辞書をインポートできる。Apple公式の書き出しplistを入口とする。26.5.2の書き出しで読みと変換先のキーを確認済み。対応範囲は複数件と対象OSの実機サンプルで検証する。 |
| R-14 | 設定画面はmacOS標準設定に近いデザインとする。ライト・ダーク両方に対応する。 |
| R-15 | 初期版に学習機能を実装しない。将来追加する場合は設定で明示的にON/OFFできることを前提に、変換器・順位制御と学習を分離できる設計とする。 |
| R-16 | 将来のGitHub OSS公開を視野に、依存・コード・辞書のライセンスと再配布条件を確認し、再現可能なビルドと第三者向け文書を整える。 |

## 3. 非目標・禁止事項

- ライブ変換、予測変換、未要求の候補表示、サジェスト
- 絵文字候補、読みから英単語への変換
- 句読点入力を契機とする自動変換・自動確定
- 初期版の学習・利用状況収集・クラウド同期
- 入力データ、辞書データ、利用状況の送信またはテレメトリ
- Intel対応
- Mac標準IMEの内部辞書・非公開データの流用
- ライセンスや権利を未確認のコード・辞書・モデルの採用

## 4. 候補順・変換品質

確定しているのは「候補順位が一貫していて予測可能」「学習で順位を変えない初期版」「ユーザー辞書を最上位」「通常変換でカタカナが漢字より先行したり逆転したりする不規則さを避けたい」という嗜好である。

具体的な漢字優先アルゴリズムは**未決**。一律に漢字を優先する案は会話中に提案された仮説にすぎず、ユーザー承認済み仕様ではない。辞書・頻度・品詞・文脈を含め、技術検証と利用者レビュー後に決める。同じ入力・同じ辞書・同じ設定なら、学習なしで再現可能な順序にする。

## 5. OSS・権利方針

公開可能性を前提に設計するが、公開するかは後日判断する。個人利用なら権利確認を省いてよい、という扱いはしない。すべての第三者コード・辞書・モデルについて、取得元、バージョン、ライセンス、改変・再配布条件、NOTICE等の要否を記録する。AppleのAPIやUIを使う場合も公開APIと規約を確認する。法的結論を推測で断定しない。

## 6. 仮説・要確認事項

- Mozcを変換エンジン候補として検討する案。採用決定ではない。
- Swift / InputMethodKit / AppKit / SwiftUI等の採用案。実現性・対応OS・保守性を未検証。
- Apple Silicon向け配布方式、署名・公証、最小対応を目指すmacOS 26.0での動作検証。
- Mac標準IMEのキー操作、候補表示、文節伸縮等の正確な対応範囲。
- Apple標準IMEのユーザ辞書plistの複数件・OS間の互換範囲。候補除外に該当する辞書語、同音複数語や複数文節での最上位規則の扱い。
- 数字や句読点以外の記号キーごとの日本語モード出力。日本語モード全角という最新の包括指定を優先するが、個別対応は確認が必要。
- 日本語モードの空状態のSpaceは全角とする。修飾付きSpace等の詳細は実機確認の対象。
- 「ひらがな変換」専用キー、Ctrl+K以外の再変換操作の詳細。
- 初期版は固定キーとする。キーバインドのカスタマイズ範囲は今後検討する。

## 7. 受入れの大枠

各段階の対象機能について `docs/TEST_SPEC.md` の該当項目を確認する。初期版の完了時には、対応OS・アプリで必要な全項目とライセンス確認を満たす。変換精度の主観評価は利用者レビューを含めて判断する。
